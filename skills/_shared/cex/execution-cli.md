# CLI Execution Rules

Use the verified Gate CLI binary as the only integration boundary. Product references define exact command paths, fields, units, and verification actions; this file defines shared invocation and result handling.

- Pass values as separate process arguments. Do not interpolate user/tool text into a shell string or execute it through `eval`.
- Use `--format json` and normally `--max-output-bytes 1048576` for business calls; authentication and version commands have their own text contracts. Keep stdout, stderr, and exit status separate.
- Read the actual per-command payload. There is no universal `success` envelope. Structured errors can appear on stderr as `{"error": ...}`; argument failures can be text.
- Preserve decimal strings and exact IDs. Use decimal arithmetic; do not silently round or change requested amounts. Time units and quantity meanings come from the product contract.
- A successful process exit or submission reference does not prove a fill, transfer settlement, or completed redemption. Query the appropriate business object before reporting that state.
- Treat an HTTP 200 business rejection or an incomplete expected result as a failure. Use a CLI build that reports the original business error; an empty object is not evidence that a create, detail or stop succeeded. Do not replay an uncertain write to obtain a clearer response.
- Treat `truncated: true` as incomplete even when exit status is zero; never count a truncation object as a list or infer totals from partial records. Narrow a subsequent read where supported. For the unfiltered, unpaginated `gate-cli cex spot market currencies` and `gate-cli cex spot market pairs` catalogs, use `--max-output-bytes 8388608` directly or for one safe retry after truncation, within the same call/deadline budget. Save stdout to a local file and parse the complete JSON array locally to count or select records; return only the requested summary. If still truncated, invalid or over the limit, stop and disclose incomplete coverage. Do not use unbounded output or repeat a write to recover its output.
- Bound reads, polling, pagination, and retries. Retry only safely repeatable operations within a fixed time/call budget; honor cancellation and service throttling. Do not multiply retries across layers.
- Use a finite per-process deadline (normally 30 seconds), at most three attempts for a safe read, and at most ten pages or 1,000 records per task unless a smaller backend limit applies. Only the two complete spot catalogs above may exceed the record budget for local parsing, within their 8MiB output cap; do not expose the full catalog to model context. Honor retry-after/backoff within the same deadline budget. A deadline is a host execution limit, not an invented CLI flag. Never automatically retry a business write. Stop and report truncation or an exhausted budget.
- Root options are `--profile` (default `default`), `--format` (default `pretty`), `--max-output-bytes`, `--debug` and `--verbose`. Prefer JSON, disable unnecessary diagnostics, and do not use unbounded output for broad queries. `--api-key` and `--api-secret` exist but must not carry secrets through process arguments. Use the approved local credential setup instead.
- Flags using Unix timestamps follow their own contract, normally seconds; CFD/stock response-envelope timestamps are milliseconds. The SDK can expose numeric JSON fields as floating point: do not derive executable financial quantities from rounded values. Use exact product precision and decimal strings, or stop when precision cannot be established.
- On an ambiguous write timeout, lost response, or interrupted process, retain the original account/context and reconcile first. Do not change references, switch transports, or replay the batch.
- When reliable reconciliation is unavailable, report an unknown outcome with evidence and the next safe step. An apparently similar order or transfer is not a unique match.
- Inspect each item in partial batch results. Neither the first success nor a transport success establishes the whole batch's outcome. Some settings return failure lists even with HTTP 200; a nonzero exit can coexist with partial updates. Re-read the affected settings instead of assuming rollback or replaying the write.
- Do not create HTTP clients, signing scripts, SDK fallbacks or generic request commands to escape a missing registered CLI capability.

Use the [display templates](templates.md) to report drafts, results, and errors. Record only the minimum diagnostic information needed for recovery; redact secrets and unrelated account information.
